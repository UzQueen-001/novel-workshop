# 去 AI 味改写

改写 agent 的活只有一件：**把判定清单上的命中处改掉**。不重新判断有没有 AI 味，不顺便润色，不改清单之外的字。

## 一次只处理一个特征

派工时给每名改写 agent **一个**特征编号和对应的命中清单，它只改这一条。特征卡在 `../novel-ai-judge/references/features/` 下，共十一张。开工前读三份东西：自己那张特征卡、`../novel-ai-judge/references/not-a-tell.md`、`05_文风/文风样本.txt`。路径都相对插件根目录 `plugins/novel-workshop/`。

## 改哪里

正文里最见效的是**血肉**（描写）与**软骨**（过渡）——AI 痕迹集中在评论式起段、翻译腔句式、堆砌的排比和破折号上。

**骨架段不动。** 骨架承载事件，改骨架段等于改事件本身，那是越界。骨架段只做一件事：看它的表述有没有被 AI 腔污染到影响理解。有就报告，由作者决定是否回炉，不自行改写。

## 先读文风样本

改写前读 `05_文风/文风样本.txt`。它的句长分布、标点习惯、用词偏好就是判断依据。

**文风样本与规则冲突时，以文风样本为准。** 作者本来就爱用破折号，就不该按规则删。参照书目里的高分作品只当对照，不当模板。

## 硬边界

- **白名单** —— 只改自己那张特征卡覆盖的规则，而且只改判定清单上列出的位置。卡上没有的、凭一般写作经验觉得「不太像人写的」，一律不动。
- **最小改动** —— 命中规则时只改解决该问题必需的部分，不顺便润色，不替换没问题的词。
- **信息守恒** —— 不新增也不删减。姓名、数字、日期、引语、来源、因果、动机，一个都不许自己长出来；限定词与让步（「可能」「通常」「据说」）不许抹掉，判断强度不许加重。改写后每个实词都要能在原文里指出出处。
- **结构守恒** —— 段落数量与顺序、对话、分段方式全部保留。
- **拿不准就保留原文。**

## 流程

1. 收下判定清单，锁定原文，通读 `05_文风/文风样本.txt`；
2. 只改清单上列出的位置，每处限定在解决该问题必需的范围；
3. 用 [references/checklist.md](references/checklist.md) 逐项复查；
4. 输出改写后的全文。不必解释改了什么，作者问再说。

## 落在流程的哪一步

降维线的第五道工序「成文」本来就只允许词汇与语序调整，本技能正好落在那一步。升维线走完生成后独立跑一遍。两条线跑完，各自的产物都清过一遍再进校准。

顺序不能反：先由 `novel-ai-judge` 判定，再交这里改写。同一名 agent 不许又判又改，编制见 `novel-panel`。
