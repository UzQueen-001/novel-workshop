# 引导工作流

## 开工第一件事

先检测这台机器上有没有 Obsidian：macOS 看 `/Applications/Obsidian.app` 在不在，其他系统查常见安装目录和 `command -v obsidian`。查一次就够，之后不再提。

**没装：一个字都别提。** 不劝装、不问要不要装、不说「建议装一个 Obsidian」。直接在普通文件夹里建同一套文件往下走——所有工作流只依赖纯 Markdown 文件，Obsidian 只是个查看器。

**装了：先问再用。** 一句话问清楚，例如「检测到你装了 Obsidian，这个库要建在 Obsidian 里吗」。得到同意再往下；用户说不用，同样按普通文件夹走。

无论走哪条路，接着都要问同一件事：**文件放在哪。** 用户没指定位置时，默认建在 `~/Documents/ChatGPT/小说库/<书名>/`，并把最终路径报给用户。建在 Obsidian 里的，多提醒一句：在 Obsidian 里「打开文件夹作为仓库」选中这个目录。

## 库的第一批结构

引导阶段只建这些，剩下的留给筹备工作流：

```text
<书名>/
|-- 00_台账/
|   |-- 提问台账.md      主线与分支提问的全部记录
|   `-- 待解决问题.md
|-- 01_世界/
|   |-- 世界观.md
|   `-- 总体矛盾.md
|-- 02_人物/
|   |-- 主角.md
|   `-- 配角_<名>.md
|-- 03_规划/
|   `-- 长线计划.md      作者已有的跨章、卷级打算，原样记，不替他细化
`-- 04_章节/
```

## 提问机制

这是本工作流的核心，必须严格执行。

**一次性登记，逐条提问。** 进入一个主题时，先把该主题下所有要问的问题一次性生成，全部写进 `00_台账/提问台账.md`，然后才逐条发问。同一时刻只问一条；拿到回答立刻落盘、更新状态，再问下一条。不要边想边问。

台账每条包含：编号、层级（主线／分支）、父编号、主题、问题、状态。

**分支处理。** 用户的回答引出新问题时，先判断它算不算分支：必须解决才能继续当前主线，算分支；只是补充信息，直接记录，不算分支。

判定为分支时做三件事：

1. 把分支问题登记进台账，标上父编号；
2. 明确告诉用户：「主线提问在第 N 条被打断，进度已保留；这个分支解决后，会从第 N 条继续。」
3. 进入分支逐条提问。

分支内部再出分支时同样提醒、同样保留，于是形成栈：先解决最内层，再回到上一层被中断的那条问题继续往下。任何时候都不要默默切换话题。

## 启发式、询问式

不替用户做设定决定，也不要一次抛出串待填空格。用具体情境把设定逼出来：

- 先给 2–4 个互斥方向做候选，再留一个开放项；
- 把抽象问题落到场景上——不问「你的能力体系分几级」，而问「主角第一次动用它时，旁观者看到什么，他自己付出什么代价」；
- 用户给出答案后追问边界：谁能做到、谁会反对、代价是什么、什么条件下会失效。

## 采集范围

| 主题 | 要采集到的程度 |
| --- | --- |
| 世界观 | 世界怎么运转、规则与代价、势力与地理、普通人怎么活 |
| 总体矛盾 | 全书核心冲突、谁与谁争什么、为什么无法立刻解决 |
| 主角 | 起点、欲望、缺口、能力、底线、会做什么不会做什么、弧线方向 |
| 重要配角 | 与主角的关系、自己的目标、和总体矛盾的接口 |
| 长线计划 | 作者已经想好的跨章、卷级打算。原样记进 `03_规划/长线计划.md`，不追问节奏、不催他细化 |
| 执行细节 | 书名、题材、目标篇幅、面向读者、更新节奏等他真正在意的执行项 |

逼不出来的答案不要硬逼，登记进 `00_台账/待解决问题.md`，标清它卡住的是哪一条。

人物卡落盘时直接带上固定小节，别写成一段散文：起点、欲望、缺口、能力与代价、底线（会做什么、不会做什么）、弧线方向、与总体矛盾的接口。配角用同一套小节，暂时写不满的先空着。

## 收尾

每一层设定都讨论到用户明确点头才继续下一层。台账条目全部关闭后，输出一份「引导完成清单」：已定的设定、未决的问题、筹备阶段要补的东西，然后交棒筹备工作流。
