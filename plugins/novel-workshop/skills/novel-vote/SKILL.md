# 多 Agent 多维投票

## 评分维度与权重

默认权重如下，筹备阶段已经把这份落进 `00_台账/评审维度与权重.txt`。作者要改就改那份，此后投票一律按它执行。

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 逻辑 | 0.18 | 因果是否闭合，有没有靠巧合过关 |
| 描写 | 0.14 | 感官与细节是否具体、必要、不堆砌 |
| 节奏 | 0.14 | 长短段配比、松紧交替、该快的地方有没有拖 |
| 人物一致性 | 0.14 | 言行与人物卡、角色状态是否咬合 |
| 信息控制 | 0.12 | 读者与角色各知道什么，有没有泄漏或藏得太死 |
| 文风贴合 | 0.10 | 与 `05_文风/文风样本.txt` 的参数是否一致 |
| 情绪张力 | 0.10 | 该揪心的地方揪不揪得住 |
| 新颖度 | 0.08 | 有没有落入套路化处理 |

## 投票怎么跑

- 至少 3 个评审 agent，互盲：各自独立打分，不看别人的分数，也不被告知自己在评哪条线的产物；
- 候选按段类型分组评：骨架段、软骨段、血肉段各评各的，只在同类之间比较，不跨类打分；
- 每个 agent 对每个候选片段逐维度打分，0–10 分，可到一位小数；
- 打分时对着 `05_文风/参照书目.txt` 与 `05_文风/参照段落.txt` 里的同类写法比，说明为何高于或低于它；
- 取各 agent 的平均分，按权重求和，得该片段的综合分。

## 互盲怎么保证

- 每个评审 agent 带独立上下文，看不到别人的评分与评语；
- 交给 agent 的候选片段打乱顺序、去掉来源标识，它不知道自己在评线1还是线2；
- 分数与评语分开回收，全部收齐之前不给任何人看；
- 收齐后统一算平均。中途不许「参考一下别人的意见」再改分。

## 结果怎么用

- 每段综合分最高的那个候选入选，三类段各选各的最优，再拼成 `缝合文章.txt`；
- 得分、各维度明细、两条线在各步的平均分写进 `00_台账/评分台账.txt`；
- agent 的评语要写下来，但只进台账，不进正文。

## 台账格式

按章、按步骤记录，每步两行（线1一行、线2一行），列：章号、步骤、派生产物、各维度平均分、加权综合分、评审 agent 数量。步骤至少覆盖首次生成、交叉创作后、缝合终选。这是日后判断「哪条线在哪一步更强」、以及比较缝合前后效果的唯一数据来源，不许估算，不许凭印象填。

## 跨章汇总怎么看

台账攒到三章以上再看趋势：

- 按「步骤 × 维度」聚合两条线的平均分，看差值，而不是只看单章总分；
- 样本不足三章，两分以内的差距不下结论；
- 只看总分容易被题材带偏，要看这条线在哪些维度上**稳定**占先，那才是它的真实强弱；
- 结论写进评分台账末尾，注明依据了哪几章。
