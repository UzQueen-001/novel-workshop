# 骨架模块

> 整个体系的核心。骨架是一条**写作顺序**的直线，展示剧情走向，管线索的出生与回收。

## 一、形态：一条直线

- 横轴 ＝ **写作顺序**。B01、B02、B03……一路往下，就是一条线。
- **线（视角）是块的一个属性**，不是并排的车道。换线 ＝ 换一双眼睛，写作顺序照旧往前走。
- **块的绝对时间是故事里的时间**，可以往回跳：编号往后、日期往前，表示「我去写更早的时间了」。
  这是回溯，不是并行。

```text
B01  L1  在一栋废楼里醒来            元年·第三日      320
B02  L1  发现这楼不按常理运转        元年·第三日      260
B03  L2  带队越过警戒线，进楼        元年·第三日      340   ← 换线
B04  L1  撞上那个孩子                元年·第三日      360   ← 换回
 ⋯
B12  L2  退回三十年前                元年前三十年     260   ← 回到过去
```

**一条硬规矩：不许摆并行泳道。** 把同时发生的事画成并排的两条轨道，写作顺序就没了，
agent 会立刻乱掉——分不清下一块该写哪里。

## 二、文件结构

```text
骨架/
  线索引.md              线的定义（L1 ＝ 谁）+ 游标
  写作顺序.md            一张表，按写作顺序排（检索目录，只放简述）
  块/
    B01_在一栋废楼里醒来.md
    B02_楼不按常理运转.md
```

目录与内容分开：`写作顺序.md` 是索引，每块的内容在自己的块文件里。

表头固定，空白列要留 `| |`：

```text
| 块 | 线 | 简述 | 时间 | 时间位 | 预估 | 标签 | 状态 |
| B07 | L1 | 隔壁屋里议论该往哪一栏记，队长把那个字抹掉 | 元年·第五日 | 5 | 380 | C01入 换线 | 已规划 |
```

**时间位**是一个可比较的数字（越小越早），只给排序用。
图上「按故事时间」那根横轴靠它——回到过去的块，时间位是负的，就会跑到左边去。

## 三、块文件里放什么

| 字段 | 说明 |
| --- | --- |
| ID | `B07`，**编号即写作顺序**，永不复用 |
| 线 | `L1`——这一块用谁的眼睛看 |
| 绝对时间 | 故事内的时间点，允许往回走 |
| 时间位 | 上面那个时间的排序键（数字） |
| 简述 | 一句话。**它就是锚**，引用时连简述一起写 |
| 在场 | 谁在这个块里 |
| 发生 | 这一段发生什么 |
| 变化 | 关系／认知／信息怎么变了 |
| 预估字数 | 10–1000 之间，**由节奏评分决定**（见第七节） |
| 标签 | `C01入` `C01出` `C01提及` `#作者定` `🔒锁定` `⚠不可逆` `🕳远端` `↩回到过去` |

## 四、连线

骨架连线**一律实线**；两块之间取**最近的两个点**（上／下／左／右四个口里挑）。

| 连线 | 含义 | 怎么标 |
| --- | --- | --- |
| 顺序 | 写作顺序的下一步 | 实线，默认不标 |
| 换线 | 换一双眼睛 | 线上注 `换线 → L2 队长` |
| 时间跳跃 | 隔了多久 | 线上注 `相对时间 +91日` |
| 回到过去 | 编号往后、日期往前 | 线标紫，注 `↩ 回到过去` |
| 因果 | 角色卡被改写 | 挂在块上，指向改写记录 |
| 线索 | 入 → 出 | 走上方弧线，**中点挂一个可点的小方块** |

回到过去的连线**不标相对时间**——绝对时间自己会说明它回到了哪。

## 五、必须打标的结构

| 标记 | 是什么 |
| --- | --- |
| `🕳远端` | 为接住线索提前立好的孤立落点块，前面还没铺到 |
| `⚠不可逆` | 死亡、势力覆灭、能力公开这类；约束该角色在此时间之后的块 |
| `↩` | 回到过去。编号仍往后走，故事时间往回走 |
| `🔒锁定` | 作者原文，一字不改 |

## 六、规则

1. **＋20k**：写作位置**之后**的块（B 编号更大的一律算），预估字数累计 ≥ 20000 才允许开工。
   骨架是唯一一条线，所以没有跨线合并的问题。
   精妙的伏笔可以让你提前把某段做长做细——只能多，不能少。
2. **持续延伸**：血肉由作者下指令持续生成（如「继续写 3000 字左右」），没有章节限制。
   作者划章，划章不进本模块。
3. **延伸时冒出的东西立刻分流**：新角色 → 待立卡队列；新地点 → 待建场景队列；
   关系变化 → 关系变更队列；线索 → 线索模块。分流完再继续规划。

## 七、节奏（块的字数从哪来）

字数不是拍出来的，是**评出来的**。每块打三个分：

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 内容重要性 | 1–5 | 这块对全局有多要紧 |
| 情绪塑造 | 紧张 / 平缓 / 悲伤 / 快乐 | 这块要什么情绪，附强度 1–5 |
| 前后节奏联系 | 1–5 | 它与前后块的咬合有多紧 |

综合分 `S = 重要性×2 + 前后联系×1 + 情绪强度×1`，范围 4–20，映射到字数：

| S | 字数 |
| --- | --- |
| 4–7 | 10–150 |
| 8–11 | 150–350 |
| 12–15 | 350–700 |
| 16–20 | 700–1000 |

**权重和分档都是暂定的，等作者调。** 一边排块一边算分，累加就是 ＋20k 那个数。

## 八、接口

- 线索模块引用块 → 用 `块ID ＋ 简述`
- 角色卡的改写挂到块上 → 见 `角色模块.md`「因果链接」
- 检查器按块读 → 见 `检查模块.md`
- 可视化按写作顺序渲染 → 见 `可视化模块.md`

## 九、纪年

绝对时间用**故事纪年**，具体纪年法由**世界观模块**决定并写死（见 `世界观模块.md`）。
骨架不另立一套时间体系；要改纪年就回世界观模块正式修订。
