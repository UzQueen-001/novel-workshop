# 角色模块

> 一个大积木＝一张角色卡；小积木＝卡上的一个字段，**一块一个 md**。

## 一、文件结构

```text
角色/
  卡索引.md               所有角色的名录（只列名字与链接）
  主角/
    卡.md                 索引＋速查表，不装正文
    积木/
      姓名.md
      出身.md
      能力与代价.md
      底线.md
      弧线方向.md
    认知边界.md            ★ 挂在卡的右边
    认知边界_更新记录.md   ★ 挂在认知边界下面
    变更/
      01_不再易怒而是悲观.md
```

## 二、积木清单

沿用一套已经跑通的分段，再补运行参数：

**设定积木（不常变）**
姓名 / 称呼 / 外形 / 登场 / 出身 / 身份实质 / 能力 / 异常 / 代价 / 做法 /
核心欲望 / 缺口 / 底线（会做什么、不会做什么）/ 弧线方向 / 与总体矛盾的接口 / 终局

**运行积木（每块都可能变）**
位置 / 目标 / 掌握的信息 / 身体与心理状态 / 与他人关系 / 变更章节

每块必填的只有：**名字、定位、来历、能力或手段、底线、当前目标**。
这六块不全，不算「完成创建」。

## 三、认知边界（挂在卡的右边）

每个角色旁边挂一份「他知道什么」：

```text
认知边界.md
  知道   自己不是人、这一行的规矩             ← 自 B24 起
  不知道 自己是按哪一栏登记的
  误以为 队长知道他的来历
  来源   B19 队长亲口说的 / B31 自己推出来的
```

判定依据是**块**，不是章。其下的 `认知边界_更新记录.md` 逐条记：
哪一块、知道了什么、从哪知道的。写血肉前读它，防上帝视角泄漏。

## 四、门禁：新角色必须先立卡才能入戏

1. 骨架延伸时冒出新角色 → 进**待立卡队列**，不直接进剧情
2. 正式角色必须补齐六块必填积木，才允许出现在任何块里
3. **无名角色**只填五块以内（出现处、功能、外形一句话、有无台词、是否复用），
   登记在册但不立卡
4. 无名角色**一旦第二次出现或被点名，必须升级**为正式角色、补齐全套

## 五、因果链接（信息改写模块）

改写不是改文字，是**在骨架某块上挂一个因果节点**，声明角色属性从此改变。

```text
变更/01_不再易怒而是悲观.md
  挂在   B22
  原值   易怒（见 积木/性格.md 基础值）
  改为   容易悲观
  原因   B21 他被同伴当面否掉，没人替他说话
  生效   自 B22 起，往后一律按新值
```

于是角色的每个字段实际是 **基础值 ＋ 变更链**。
检查器查第 N 块时，取那一刻还在生效的那一版。

**一条硬规矩**：改写可以随便挂，但**不得落在已经写完的正文里**。
撞到已写区域时停下来问作者：改回去（进待回改队列），还是让新值从后面某块才开始生效。

## 六、接口

- 线索模块可以拿角色的某个字段当入点或出点
- 检查器读卡＋认知边界＋变更链，逐块判 OOC
- 可视化把变更链画成属性随块变化的一条线
