# 命名与目录

> 可视化要能「点块开 md」，靠的就是路径稳定。这条规范先写死。

## 一、目录结构

```text
《项目名》/
  骨架/
    线索引.md              线的定义（L1＝谁）＋三个游标
    写作顺序.md            一张表，按写作顺序排（检索目录，不记内容）
    块/
      B01_在一栋废楼里醒来.md   一块一个文件
  角色/
    卡索引.md
    主角/
      卡.md
      积木/
      认知边界.md
      认知边界_更新记录.md
      变更/
  场景/
    地点索引.md
    城郊废楼.md
  关系/
    关系索引.md
    主角_对_队长.md        一条方向一个文件，A对B与B对A分开
  线索/
    线索索引.md
    C03_名字里的那个字.md
  世界观/
    世界观索引.md
    规则/ · 术语表.md · 组织与势力.md · 禁忌.md · 待解决问题.md
  文风/
    文风规范.md            可测口径（自查用）＋长短交错＋情绪两层
    人物口吻.md            每个有名字的角色一份口吻卡
  正文/
    未切稿.txt            连续文本，**不按章分文件**
  _检索/
    作者决定.md            所有 #作者定 的汇总
    待办队列.md            四类队列＋状态
```

**两条注意**：

1. 骨架与角色**不再按线分文件夹**。骨架只有一条写作顺序，线只是块上的一个字段。
2. **正文不分章存**。划章是作者的事，agent 一旦把文本切成「第N章」，就等于替作者划了章。
   一份连续文本往下写，作者自己切。

## 二、ID 规范

| 类型 | 形式 | 例 |
| --- | --- | --- |
| 骨架块 | `B` ＋ 序号 | `B07`（**编号即写作顺序，永不复用**） |
| 线 | `L` ＋ 序号，映射到角色名 | `L1` ＝ 主角 |
| 线索 | `C` ＋ 两位序号 | `C03` |
| 地点 | `场-名` | `场-城郊废楼` |
| 角色 | 直接写名字 | `主角` |

废弃的块留着占位，不删号——删了号，后面所有引用都要跟着动。

## 三、引用写法

引用骨架块一律 **`块ID ＋ 简述`**，不写纯编号：

```text
B11 他自己认下了那个字的含义
```

人和 agent 都认得出，图上也直接画得出来。

## 四、tag 规范

| tag | 用途 |
| --- | --- |
| `#作者定 YYYY-MM-DD` | 作者拍板的决定。同时汇总进 `_检索/作者决定.md` |
| `🔒锁定` | 作者原文，一字不改，直接嵌入 |
| `⚠不可逆` | 死亡、势力覆灭、能力公开这类锁死后续的块 |
| `🕳远端` | 为接住线索提前立好的孤立落点块 |
| `↩回到过去` | 编号往后走、故事时间往回走 |
| `C03入` `C03出` `C03提及` | 线索接线标记 |
| `换线` | 这一块换了视角 |
| `相对时间 +91日` | 与前一块隔了多久 |

## 五、文件格式

- 设定、骨架、台账、线索、角色卡 → `.md`
- 小说正文 → `.txt`
- 表一律固定列序，**空白列留 `| |`**（列是按位置读的，省掉就串位了）
- 宁可竖着排，不要横着摊（旧的六列伏笔台账就是反面教材）
