# 模块化写作体系 · 总纲

> 2026-10-08 立。**本项目此后按这套走**，取代原《小说工坊》的「升维解剖 ＋ 升维／降维双线生成」。
> 已经在旧体系里开写的项目可以按旧法收尾，不强制迁移。

## 一句话

一本小说拆成若干模块，每个模块由大量小块（积木）组成，**一块一个文件**；
写作时只加载当前用得着的那几块，模块之间靠连线对接。

## 为什么这么拆

- 长 md 卡顿、读不动 → 一块一个文件，一个模块就是一个 md 集群（目录）
- agent 没有跨会话记忆 → 记忆只能落在「文件 ＋ 触发规则」上
- 检查要能真跑起来 → 每个模块配一个独立检查器，按块读、按块判

## 四条基础约定

1. **格式**：设定、骨架、台账一律 `.md`；小说正文一律 `.txt`。
2. **粒度**：一个小积木一个 `.md`；一个模块是一个目录。
3. **取向**：**可视化可读性优先，内容可读性其次**。文件是给图读的，也是给人扫的，不是散文。
4. **ID**：稳定、简短、读得出。见 `命名与目录.md`。

## 时间坐标系

- 骨架横轴 ＝ **写作顺序**，一条直线：B01、B02、B03……一路往下
- **线（视角）是块的一个属性**，不是并排的车道。换线 ＝ 换一双眼睛，顺序照旧往前走
- **块上挂**故事内绝对时间，可以往回跳（编号往后、日期往前 ＝ 回到过去，不是并行）
- **连线上挂**相对时间；回到过去的连线不标相对时间，绝对时间自己会说明

**不许摆并行泳道。** 同时发生的事一旦排成两条并排轨道，下一块该写哪里就分不清了。

绝对时间用**故事纪年**，纪年法由世界观模块定（见 `世界观模块.md`）。

## 三个游标

| 游标 | 含义 |
| --- | --- |
| 已规划到此 | 骨架里最后一个已经写了内容的块 |
| 写作位置 | 正文已经写到的那个块 |
| +20k | 写作位置**之后**的块，预估字数累计 ≥ 20000，才允许开工（一条线，没有跨线合并问题） |

## 流程

三步，只有一条反向路。

1. **骨架生成**——重头戏。要同时考虑多方面因素、信息的交流与修改、连贯性与合理性。
   产出块、连线，以及每块的**节奏评分**（字数由评分决定，见 `骨架模块.md`）。
2. **血肉填充**——几乎单向：按骨架写 → 检查 → 修改。
   写到哪停由作者发指令（如「继续写 3000 字左右」）。
3. **回退**——血肉写了一半发现走不通，允许回头改骨架。这是唯一反向的路。
   改骨架时要顺带查影响面：挂在这块上的线索入出、角色改写、关系变更要不要跟着动。

**没有独立的「书写模块」——书写就是照骨架写。**
骨架生成要交代清楚的是**分析**（连贯性、合理性、信息交流），血肉填充要交代清楚的只有**检查与修改**。

## 通用规矩

- 每个模块配一个独立检查模块，填血肉后运行（见 `检查模块.md`）
- 作者的决定**就地打 tag**：`#作者定 YYYY-MM-DD`，另有一份检索文本汇总
- 每条待办队列都带状态：未处理 / 处理中 / 已完成
- **检查器的有效性上限 ＝ 台账的完整度**。检查器只能发现「和记录冲突」，发现不了「记录里根本没写」

## 文风

**最初撤销，2026-10-08 恢复成最小模块。** 撤销的理由是：文风不是靠规则约束出来的，
落笔的终究是 agent 自己。但一轮三万字跑下来证伪了这条——**没有可测的约束，
agent 会一律写成短句加句号**（叙述句均长只有作者原稿的三分之一）。

所以恢复的**只**是两样可测的东西，不碰语感：

1. **可测口径表**（句长分布、标准差、标点密度）——只用于**事后自查**；
2. **人物口吻卡 ＋ 状态曲线**——治千人一面。

细则见 `文风与口吻.md`。定稿前仍走一遍**去 AI 味**的判定与改写。
