# 线索模块

> 取代旧的伏笔台账。旧台账是一张六列宽表，读起来费劲，效果也不好。

## 一、本质

一个**一入一出的连接模块**。它只负责记录：这条线从哪儿起，到哪儿收。

**出口没规划就是有问题。** 线索诞生的那一刻，就必须同时具备：

- 一个**预期落点**（出口块）
- 那个落点的**预期剧情**
- 落点**前后各一块**剧情（把它夹住）

什么时候真正穿起来不管，但必须先站着。于是：

```text
埋线 → 立刻往后（可能很远）定出落点 → 补落点前后各一块 → 线索才登记成功
```

这条规则的真实效果：**把「以后再说」从流程里删掉了**。

## 二、记录格式（一条线索一段，不用宽表）

```text
C03 · 名字里那个多出来的字
  入   B06  几个人议论该往哪一类写，有人嘴里溜出一个字，队长抹掉
  出   B31  他自己认下这个字的含义
  前   B30  他第一次在册子上看见自己的名字
  后   B32  他问队长这字是什么意思，队长不答
  状态 已规划
  备注 作者标注：不许提前解释，出口只给一半
```

一条线索一份 md，放在 `线索/C03_名字里的那个字.md`。

## 三、提及：骨架指向线索，不是线索的一条边

一条线在中途被别人提过、瞥见过、绕了个弯——这叫**提及**。
提及**不算回收**，也不进线索模块的入出。

```text
骨架块   B06 几个人议论该往哪一类写，队长抹掉那个字   C03入
         B14 他听见别人嘴里又溜出那个字               C03提及
         B19 他盯着册子上那一栏看了很久               C03提及
         B31 他自己认下这个字的含义                    C03出
```

**线索模块自己只有两行是它的**，其余全挂在骨架上。
要全貌就去骨架里扫同一个 C 编号，出入和提及全在。

## 四、判定

**只看有没有「出」。** 提及再多也不算回收。
一条线可以挂十个提及、一个出都没有，照样报警。

## 五、状态

| 状态 | 含义 |
| --- | --- |
| 已规划 | 出口块已经站在骨架里（**登记成功的最低要求**） |
| 已回收 | 正文写到出口块了 |
| 已废弃 | 作者明确砍掉，写明原因与影响面 |

出口没规划出来的线索**不允许存在**，所以没有「悬空」这个状态。

## 六、接口

- 入点／出点引用骨架块：`块ID ＋ 简述`
- 落点若是远端块，该块要打 `🕳远端`
- 检查器只查「有入无出」和「入出指向不存在的块」
