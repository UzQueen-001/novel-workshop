# 人物关系模块

> 一组线。**A 对 B 和 B 对 A 各存一条，不合并。**

## 一、一条关系线是什么

一对人物 ＝ 两条有方向的线。A→B 一条，B→A 一条。
不写成「他们是朋友」这种合起来的说法。

```text
关系/主角_对_队长.md
  方向   主角 → 队长
  看法   带我出来的人；名字是他给的
  类型   恩人（主）/ 上下级（次）
  联系   天天见，被安排跟着他
  变更   B31 起，类型加一项「债」——他开始觉得自己欠着队长
```

**字段**：方向 / 看法 / 关系类型 / 联系方式 / 起点块 / 变更 / 标签。

关系类型的词：利益、恩人、好友、上下级、血亲、仇、债、陌生人……可多个，**按主次排**。

## 二、为什么必须分开

A 觉得是好友，B 觉得是恩人——**这种不对称本身就是戏**。
合并成一条，这层张力当场写丢，检查器也无从查起。

## 三、挂载改写

和角色卡的因果链接同一套机制：在骨架某块上挂一条改写，
看法或类型从此改变。旧值作废，新值生效，检查器按块取当时生效的那一版。

## 四、可视化

两个人之间画**双向箭头**，两个方向的标签各写各的；
两边判定不一致时高亮——**不对称一眼看得见**。

## 五、接口

- 骨架延伸时关系发生变化 → 进待办队列「关系变更」，处理完才继续规划
- 检查器读关系线，查新血肉有没有越界（B 对 A 还戒备，血肉里却写成老友）
- 关系类型的词尽量取术语表里的写法，不自造近义词

## 六、待定（这条是我提的）

关系类型要不要定一份**封闭词表**。
封闭的用起来利落，但遇到词表里没有的关系得停下来加词；
我倾向开表但登记——用过的词不许换写法。
